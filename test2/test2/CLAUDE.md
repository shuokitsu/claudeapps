# CLAUDE.md

このファイルは、Claude Code（および引き継ぐ開発者）がこのプロジェクトで作業する際のガイドです。

## プロジェクト概要

ローカルで動作するピュアHTML/CSS/JavaScriptのシミュレーションRPG（ファイアーエムブレム風のグリッドベース・ターン制ストラテジーゲーム）。
サーバーやビルドツール、外部ライブラリを使わず、`index.html` をブラウザで開くだけで動作させることを目指す。

詳細な仕様は [SPEC.md](SPEC.md) を参照。まだチャットで仕様を固めている段階なので、決定事項は都度 SPEC.md に反映すること。

## ファイル構成

- `index.html` — エントリーポイント
- `css/style.css` — 見た目・レイアウト
- `js/data.js` — 地形・武器・クラス・3マップ分のデータ定義
- `js/unit.js` — ユニット生成・成長・装備
- `js/map.js` — グリッド・移動範囲(BFS)・射程計算
- `js/battle.js` — 命中/ダメージ計算・戦闘解決・回復
- `js/ai.js` — 敵フェーズの行動決定
- `js/dialogue.js` — 会話パートのデータ（ストーリー・セリフ・選択肢）と再生エンジン
- `js/render.js` — DOM描画（マップ・サイドバー・オーバーレイ・会話画面）
- `js/save.js` — localStorageへのセーブ/ロード
- `js/main.js` — 状態管理・画面遷移・イベントハンドラ
- `js/input.js` — ゲームパッド・キーボード入力（読み込み順は最後）

## 会話パートを編集する場合

- ストーリー・セリフ・選択肢はすべて `js/dialogue.js` の `DIALOGUES` オブジェクトにまとまっている。マップごとに `intro`（開始前・選択肢あり）と `outro`（クリア後）を持つ
- 話者は `CHARACTER_INFO` で定義（leon/gareth/mirei/celia）。表示は左＝レオン固定、右＝会話中の相手が自動で切り替わる仕組み（`render.js` の `renderDialogueLine`）
- 選択肢の `mod: {atk, def}` が、その章の敵ステータスに加算される（難易度分岐）。ストーリーやセリフを増やす場合はこのファイルだけ編集すればよい
- `.claude/launch.json` — 開発確認用のローカルサーバー設定（`python -m http.server`）。ゲーム自体はサーバー不要

## 既知の未調整事項（プレイして調整する想定）

- ユニット・武器の数値バランス（SPEC.md 13章）
- 移動確定後に「戻る」操作ができない（一度移動をクリックすると確定。仕様として意図的に簡略化）
- セーブは1スロットのみ、いつでも上書き保存可能

## 入力方式（マウス／タッチ／キーボード／ゲームパッド）

- 基本操作はマウスクリック（＝タップ）。`js/render.js` が生成するタイル・ボタンのclickイベントがすべての起点で、タッチもブラウザ標準のtap→click変換でそのまま動く
- キーボード（矢印キー＋Enter/Space=決定＋Escape/Backspace=キャンセル）とゲームパッド（D-pad/左スティック＋Aボタン=決定＋Bボタン=キャンセル）は `js/input.js` で処理。どちらも同じ `handleDirection`/`handleConfirm`/`handleCancel` を呼び、最終的に既存の `window.onTileClick` などクリック用ハンドラを呼ぶだけなので、ロジックの二重実装はない
- カーソル操作を一度使うと `state.usingCursor` がtrueになり、マップ上にカーソル枠・ボタンにフォーカス枠（`.gp-focused`）が表示されるようになる（マウスのみで操作している間は表示しない）
- スマホ向けには `css/style.css` に幅700px以下のレスポンシブ対応（サイドバーをマップ下に縦積み、ボタンを大きく）と、タップ時のズーム/選択/ハイライト抑制（`touch-action`, `user-select`, viewportの`user-scalable=no`）を追加している

## 開発方針

- フレームワーク・ビルドツール不使用（ピュアHTML/CSS/JS）
- 外部ライブラリのCDN読み込みも基本的に行わない（完全ローカル動作を優先）
- ロジックは `js/` 配下に機能単位で分割する（map / unit / battle / ai / render など）
- 画像アセットを持たない構成のため、表示ロジック（render）はデータ（unit/mapの状態）から分離し、後で画像アセットに差し替えやすい構造にする
