# サウンドノベルゲーム 仕様書

## 概要
- HTML/CSS/JSで実装するサウンドノベル（ビジュアルノベル）ゲーム
- ローカル環境で動作（ブラウザでindex.htmlを開くだけで起動）
- PCゲームコントローラーに対応（Gamepad API使用）

## 起動方法
`index.html` をブラウザで直接ダブルクリックして開くだけで動作する（`fetch()` を使用していないため `file://` でもCORSエラーは発生しない）。
開発中の動作確認には `.claude/launch.json` に設定したローカルサーバー（`python -m http.server`）も利用可能。

## 技術構成
- ピュアHTML/CSS/JS（ビルド不要、フレームワーク・パッケージマネージャ不使用）
- ブラウザで直接 `index.html` を開いて動作することを前提とする
- シナリオデータは編集しやすい独自のテキスト形式で管理し、専用パーサーで読み込んで再生する

## 必須機能
1. **テキスト表示**
   - 話者名 + 本文の表示
   - クリック / コントローラー操作でテキスト送り
   - バックログ（既読ログ）の各行はクリック可能で、その行が表示された瞬間のシーン・状態（背景/立ち絵/BGM・フラグ）に戻ってゲームを再開できる。それより後のログ（まだ起きていない内容）は破棄される
2. **分岐選択肢**
   - 選択肢を表示し、選んだ内容によってシナリオが分岐する
3. **セーブ / ロード**
   - `localStorage` を使用して進行状態を保存・復元する
   - セーブスロットの削除も可能（誤操作防止のため、削除ボタンは2回クリック方式：1回目で「本当に削除？」表示に切り替わり、3秒以内の2回目クリックで削除確定）
   - バックログ（既読ログ）もセーブデータに含め、ロード時はそのセーブ地点までの実際の会話ログを復元する（ロード前に読み進めていた分や、それより前の周回のログは引き継がない）
4. **BGM・効果音**
   - シーンごとにBGMを再生・切り替え
   - イベントに応じて効果音を再生
5. **立ち絵・背景画像表示**
   - 背景画像の切り替え
   - キャラクター立ち絵の表示・切り替え（位置指定: 左/中央/右 を想定）
6. **オート再生**
   - クリック・ボタン操作なしで自動的にテキストが進行するモード
   - 選択肢が表示された場合はオート再生を一時停止する
7. **設定画面**
   - テキスト表示演出（タイプライター風 / 瞬間表示）を切り替え可能にする
   - その他表示・音量設定などをまとめる画面
   - 進捗状況のリセット（セーブスロット・分岐マップの記録をすべて削除）。誤操作防止のため、他の削除操作と同じ2回クリック方式（1回目で「本当に削除しますか？」表示に切り替わり、3秒以内の2回目クリックで削除確定）。実行後はタイトル画面に戻る
8. **分岐マップ（フローチャート）**
   - これまでにプレイヤーが実際にたどったシーン・選択のみをグラフ表示する（未選択の分岐は表示しない）
   - ノードをタップすると、そのシーンにジャンプしてゲームを再開できる
   - タイトル画面・ゲーム中HUDの両方からアクセス可能
   - セーブスロットとは独立してグローバルに進捗を記録し、分岐達成率（到達可能な全シーンに対する訪問済みシーンの割合）を表示する
   - 詳細は後述の「分岐マップ機能」セクションを参照

## システム設定ファイル
セーブスロット数などアプリ全体の設定は `scenario/` とは別に、システム設定ファイル（例: `config/system.json`）で指定する。

```json
{
  "saveSlotCount": 3,
  "textSpeedDefault": "typewriter",
  "autoPlayIntervalMs": 1500
}
```

- `saveSlotCount`: セーブスロット数（初期値 3）
- `textSpeedDefault`: 初期状態のテキスト表示演出（`typewriter` または `instant`）。設定画面でユーザーが変更した値は別途 `localStorage` に保存し、次回起動時に反映する
- `autoPlayIntervalMs`: オート再生時、1行の表示完了から次の行に進むまでの待機時間（ミリ秒）

## コントローラー操作仕様（Gamepad API）
| 入力 | 動作 |
|---|---|
| Aボタン | テキスト送り / 選択肢の決定 |
| 方向キー 上下 | 選択肢のカーソル移動 |
| Bボタン | バックログ表示 / 戻る |
| Startボタン | メニュー開閉 |

※ キーボード・マウス操作（クリックでテキスト送り等）も併用できるようにする。

## シナリオデータ形式（独自テキスト形式）
JSON/JSオブジェクトを直接書くのは編集しづらいため、シナリオは行指向の独自テキスト形式で記述する。`js/scenario-parser.js` がこのテキストを解析し、エンジンが扱うシーン/コマンド構造に変換する。

> **実装上の注意**: `index.html` を `file://` で直接開く運用のため、テキスト本体は `.txt` ファイルではなく `window.SampleScenarioText = \`...\`;` というテンプレートリテラル（バッククォート）に格納している（`fetch()` は `file://` でCORSエラーになるため）。編集する際はバッククォートで囲まれた中身（プレーンテキスト部分）だけを書き換えればよく、JSON特有の `{}` `,` `""` は一切登場しない。
>
> シナリオ本文は1ファイルに収める必要はなく、複数のJSファイルに分割できる。`scenario/sample/` 配下の各ファイルは `window.SampleScenarioText` にテキストを追記していく形式で、最初のファイルだけ `window.SampleScenarioText = \`...\`;` で初期化し、以降のファイルは `window.SampleScenarioText += \`...\`;` で追記する（先頭で初期化してしまうと前の章の内容が消えるので注意）。読み込み順は `index.html` / `debug.html` の `<script>` タグの並び順で決まるため、章を追加・並び替える際は両方のHTMLを揃えて更新する必要がある。この方式により `js/engine.js` 側は分割の有無を意識せず、常に結合済みの1本のテキストとして扱える。

### 書式
```
# これはコメント行（無視される）

@title タイトル名

@scene シーンID
@bg ファイル名             … 背景切り替え
@bgm ファイル名            … BGM再生・切り替え
@se ファイル名             … 効果音再生
@char 位置 ファイル名       … 立ち絵表示（位置: left/center/right。ファイル名を省略 または "-" で非表示）
話者：セリフ本文            … "："（全角）または ":"（半角）より前が話者名。区切りが無い行はナレーション扱い

@set フラグ名 値            … フラグに値を設定（true/false/数値/文字列）
@add フラグ名 数値           … フラグ（数値）に加算。未設定時は0として扱う
@if 条件 => シーンID        … 条件を満たす場合のみ指定シーンへ遷移。満たさない場合は次の行へ続行（フォールスルー）

@choice
選択肢の文言 => 次のシーンID
選択肢の文言 => 次のシーンID [if 条件]        … 条件付き選択肢。条件を満たさない場合はその選択肢自体が表示されない

@jump 次のシーンID          … 指定シーンへ遷移
@end                      … シナリオ終了
```
ファイル内で最初に登場した `@scene` が自動的に開始シーンになる（`start` を別途指定する必要はない）。

### フラグ・条件分岐機能
好感度・所持アイテム・既読状態などをフラグとして持たせ、シナリオを分岐させる機能。

- フラグは `@set`（絶対値の設定）・`@add`（数値への加算）で操作する。値は `true`/`false`/数値/文字列/クオート付き文字列（`"文字列"`）を認識する
- 条件式の書式（`@if` および選択肢の `[if ...]` で共通）:
  - `フラグ名` … フラグが truthy かどうか
  - `!フラグ名` … フラグが falsy かどうか
  - `フラグ名 == 値` / `!=` … 値との比較（真偽値・文字列も含めた厳密比較）
  - `フラグ名 >= 値` / `<=` / `>` / `<` … 数値としての比較
- `@if 条件 => シーンID` は条件を満たす場合のみジャンプする「条件付きjump」。満たさない場合は次のコマンド行にそのまま進む（`@jump`と組み合わせて `@if 条件 => A` の次の行に `@jump B` を書けば if/elseのように使える）
- フラグはセーブデータに含まれ、セーブ/ロードをまたいで保持される。新規ゲーム開始時は空の状態にリセットされる
- 実装は `js/engine.js` の `evaluateCondition()`。値の型変換ロジックは `js/scenario-parser.js` の `normalizeValue()` を共有している

### 実例（scenario/sample/ の抜粋）
```
@scene scene1
@bg room.png
@bgm theme1.mp3
@char center girl_normal.png
謎の声：……やっと目を覚ましたのね。
主人公：ここは……どこだ？

@choice
「誰だ？」と尋ねる => scene2a
黙って様子を見る => scene2b

@scene scene2a
@se select1.mp3
@add trust 1
主人公：……お前は誰だ？
@jump scene3

@scene scene3
@if trust >= 1 => scene3_trusted
@jump scene3_normal

@scene scene3_common
@choice
彼女についていく => ending_true
そばにいることを申し出る => ending_special [if trust >= 1]
一人で歩き出す => ending_normal
```

### パース後の内部データ構造（参考・エンジンはこの形式のみを扱う）
`scenario-parser.js` は上記テキストを以下のようなコマンド配列に変換する。`js/engine.js` はテキスト形式を意識せず、常にこの構造だけを扱うため、将来テキスト形式を変更してもエンジン本体の修正は不要。

```json
{
  "title": "目覚めの部屋",
  "start": "scene1",
  "scenes": {
    "scene1": {
      "commands": [
        { "type": "bg", "file": "room.png" },
        { "type": "bgm", "file": "theme1.mp3" },
        { "type": "char", "pos": "center", "file": "girl_normal.png" },
        { "type": "text", "speaker": "謎の声", "body": "……やっと目を覚ましたのね。" },
        { "type": "text", "speaker": "主人公", "body": "ここは……どこだ？" },
        {
          "type": "choice",
          "options": [
            { "text": "「誰だ？」と尋ねる", "next": "scene2a" },
            { "text": "黙って様子を見る", "next": "scene2b" }
          ]
        }
      ]
    }
  }
}
```

### コマンド種別
- `bg`: 背景画像を切り替える（`file`）
- `bgm`: BGMを再生・切り替える（`file`）
- `se`: 効果音を再生する（`file`）
- `char`: キャラクター立ち絵を表示・切り替える（`pos`: left/center/right, `file`: nullで非表示）
- `text`: テキストを表示する（`speaker`, `body`）
- `set`: フラグに値を設定する（`flag`, `value`）
- `add`: フラグ（数値）に加算する（`flag`, `value`）
- `if`: 条件を満たす場合のみシーン遷移する（`condition`, `next`）。満たさない場合は次のコマンドへフォールスルー
- `choice`: 選択肢を表示する（`options`: `text` + `next` + `condition`（条件なしは`null`）の配列。条件を満たさない選択肢は表示時に除外される）
- `jump`: 指定シーンへ遷移する（`next`）
- `end`: シナリオ終了

## サンプル素材
Pythonスクリプト（Pillow + wave標準ライブラリ）で生成した簡易サンプル素材を格納済み。すべて仮素材であり、本番用のイラスト・音楽に差し替える前提。
- `assets/images/bg/room.png`: 室内背景（暖色グラデーション＋窓）
- `assets/images/bg/outside.png`: 屋外背景（空グラデーション＋太陽・丘）
- `assets/images/characters/girl_normal.png`: キャラクター立ち絵（無表情）
- `assets/images/characters/girl_smile.png`: キャラクター立ち絵（笑顔）
- `assets/bgm/theme1.mp3` / `theme2.mp3`: ループ用アンビエントBGM（正弦波合成）
- `assets/se/select1.mp3` / `select2.mp3`: 選択時の効果音（短いブリープ音）

BGM/効果音は当初ブラウザの `<audio>` 要素で直接再生できる `.wav` 形式で生成していたが、`.mp3` へ差し替え済み（Python標準の `wave` モジュールでPCMを読み出し、`lameenc` ライブラリでMP3エンコードする一時スクリプトを使用。スクリプト自体はリポジトリには残していない）。

## 素材未配置時のフォールバック仕様
背景・立ち絵・BGM・効果音の実ファイルが `assets/` 配下に無い場合でもエラーで停止しないよう、以下のフォールバックを実装済み：
- 背景画像: 読み込み失敗時は `[背景: ファイル名]` というテキストを背景レイヤーに表示
- 立ち絵: 読み込み失敗時は破線の枠＋ファイル名を表示するプレースホルダーボックスに切り替え
- BGM/効果音: 再生失敗時はコンソールに警告を出すのみで、ゲーム進行は止めない

## 開発の進め方 / 動作確認
1. サンプルシナリオ（テキストのみ、プレースホルダー表示）でエンジンの動作を確認 → **完了**（分岐選択肢、セーブ/ロード、オート再生、テキスト表示切替、エンディング分岐までブラウザで動作確認済み）
2. 素材（立ち絵・背景・音声）は後日追加予定。ファイルを対応する `assets/` 配下のフォルダに配置すれば自動的にプレースホルダーから実素材表示に切り替わる
3. コントローラー未接続時はキーボード（Enter/Space/矢印/Esc）・マウスクリックでも操作可能

## デバッグ用シナリオビューア（debug.html）
ゲーム本体（index.html）とは別に、シナリオの分岐構造をグラフィカルに確認できるデバッグ画面を用意している。ゲームのプレイには不要な開発者向けツール。

- 起動方法: `debug.html` をブラウザで直接開く（`index.html` と同様、ローカルサーバー不要）
- 表示内容: 各シーンをノード、`@choice`/`@jump` による遷移を矢印付きの線として自動レイアウト表示
- ノードをクリックすると右側パネルにそのシーンの全コマンド（背景/BGM/効果音/立ち絵/セリフ/選択肢/jump/end）と遷移元一覧を表示
- ドラッグでパン、マウスホイールでズーム、「全体表示」ボタンでグラフ全体をウィンドウに収める
- 警告の自動検出（クリックで該当シーンにフォーカス）:
  - `@choice`/`@jump`/`@end` のいずれも無いシーン（進行が途中で止まる。`@if`はフォールスルーの可能性があるため単体では終端とみなさない）
  - 開始シーンから到達できない孤立シーン
  - 選択肢/jump/ifが参照しているが実際には定義されていない未定義シーン（赤い破線のゴーストノードとして表示）
- 「フラグ」パネル: シナリオ内で使われている全フラグを一覧表示し、どのシーンで設定（`@set`/`@add`）され、どのシーンで参照（`@if`/条件付き選択肢）されているかを表示する
- `@if` による分岐、条件付き選択肢はグラフ上でオレンジ色の矢印として区別表示される
- 使用ファイル: `js/scenario-graph.js`（シナリオ解析・自動レイアウト計算）、`js/debug-main.js`（SVG描画・パン/ズーム・詳細パネル）、`css/debug.css`。`js/scenario-parser.js`・`scenario/sample/`配下の各ファイルをゲーム側と共有しているため、シナリオを書き換えれば自動的にグラフへ反映される

## 分岐マップ機能（ゲーム本体）
debug.html のグラフ表示（`js/scenario-graph.js`）をベースに、プレイヤー向けの分岐マップをゲーム本体（index.html）にも実装している。debug.html を置き換えるものではなく、別画面として共存する。

- 起動方法: タイトル画面の「マップ」ボタン、またはゲーム中HUDの「マップ」ボタンから開く
- 表示内容: **これまでに実際にプレイでたどったシーン・遷移のみ**を表示する。`@choice` で選ばなかった選択肢の先や、まだ到達していないシーンは表示しない（debug.html はシナリオ全体を表示する開発者向け、こちらはプレイヤーの既プレイ範囲のみを表示するプレイヤー向け、という違い）
- ノードをタップ/クリックすると、そのシーンの先頭にジャンプしてゲームを再開できる（タイトル画面から開いた場合もそのままゲーム画面に遷移する）
- ズームボタン（－/＋）で拡大縮小、パン操作はペイン内のスクロールで行う（タッチ端末でもそのまま使える）
- **進捗の永続化**: セーブスロットとは独立したグローバルな記録として `localStorage`（キー: `vn_flowchart_progress`）に保存する。新規ゲーム開始やロードではリセットされない（分岐達成率が「プレイ全体を通じて集めていく」指標になるため）
  - 保存内容: 訪問した各シーンについて「そのシーンに入った瞬間のview（背景/立ち絵/BGM）とflagsのスナップショット」、および実際にたどった遷移（`fromSceneId::toSceneId`のペア）
  - 同じシーンに再訪すると、そのシーンのview/flagsスナップショットは最新の内容で上書きされる。これにより「変数は、過去にさかのぼって選び直すまで最後に選択した状態を保持する」という挙動を実現している（そのシーンを経由し直さない限り上書きされない）
  - マップ経由のジャンプは `engine.start(sceneId, 0, 保存されたview, 保存されたflags)` を呼ぶだけで、これは既存のセーブ/ロード（`restoreSnapshot`）と同じ仕組みを再利用している
- **分岐達成率**: 到達可能な全シーン数に対する、これまでに訪問したシーン数の割合（例:「達成率: 11 / 19（58%）」）
- **現在たどっているルートの強調表示**: 現在地のシーンから`progress.scenes[id].from`（そのシーンに最後に入った際の直前シーン）を逆にたどり、始点から現在地までの経路を求めて強調表示する（専用色・太い線・グロー・矢印・現在地の脈動アニメーション、凡例つき）。
  - `from`は「最後にそのシーンへ実際に遷移してきた元シーン」を記録しており、同じシーンに別ルートで再訪すると上書きされる（view/flagsと同じ「最後に選択した状態を保持」方式）。マップ/バックログからのジャンプ（`from`が無い遷移）ではこの`from`を上書きしない、という1点だけ特別扱いすることで、**ジャンプでその場に来ても、それ以前の本当にプレイした経路がそのまま遡って表示され続ける**（ジャンプは「テレポート」であって「新しい経路を歩んだこと」にはしない、という考え方）
  - この方式のため、現在たどっているルートは「今のセッションで起きたこと」ではなく「記録されている最新の経路」を毎回そのつど計算し直したものになる。マップを開くたび・画面を再描画するたびに、現在地（`engine.sceneId`）を起点として再計算する
- 実装は `js/flowmap.js`（`window.FlowMap`。`traceCurrentPath()`が上記の経路逆算を担う純粋ロジック。`scenario-graph.js`は無改修のまま利用）と `js/main.js`（SVG描画・ボタン配線・ジャンプ処理）、`js/engine.js` の `onSceneEnter` フック（`runFrom(0)`呼び出し時＝シーン新規入場のたびに発火し、直前シーンID・現在のview/flagsを通知）
- 使用ファイル: `js/flowmap.js`（新規）、`js/engine.js`（`onSceneEnter`フック追加）、`js/save.js`（`loadProgress`/`saveProgress`追加）、`js/main.js`、`index.html`の`#flowmap-screen`
