# プロジェクト引継ぎメモ（CLAUDE.md）

このファイルは会話の履歴・決定事項を都度記録し、セッションが変わっても引き継げるようにするためのものです。
詳細仕様は [SPEC.md](SPEC.md) を参照してください。

## プロジェクト概要
- サウンドノベル（ビジュアルノベル）ゲームをHTML/CSS/JSで実装
- ローカル動作（index.htmlを開くだけ）
- PCコントローラー対応（Gamepad API）

## 決定事項（2026-09-04時点）
- 技術構成: ピュアHTML/CSS/JS、ビルド不要
- シナリオ管理: 独自テキスト形式（`@bg`/`@bgm`/`@char`/`@choice`等のディレクティブ + 「話者：セリフ」行）を`js/scenario-parser.js`でパースし、内部的にはシーン単位のコマンド配列（簡易ADVエンジン形式）へ変換。JSON/JSオブジェクトを直接編集する必要がないようにした（2026-09-04変更）
- 必須機能: 分岐選択肢 / セーブ・ロード・削除（localStorage） / BGM・効果音 / 立ち絵・背景画像表示 / フラグによる条件分岐（`@set`/`@add`/`@if`、条件付き選択肢）
- コントローラー操作:
  - Aボタン: テキスト送り / 選択決定
  - 方向キー上下: 選択肢移動
  - Bボタン: バックログ表示 / 戻る
  - Start: メニュー開閉
  - キーボード・マウスも併用可能にする
- コンテンツ: 現時点でストーリー・素材なし。まずはサンプルシナリオでエンジンを作る方針
- テキスト表示演出: タイプライター風/瞬間表示を設定画面で切り替え可能にする
- オート再生機能: 実装する（選択肢表示時は一時停止）
- セーブスロット数: システム設定ファイル `config/system.json` で指定。初期値3
- システム設定ファイル `config/system.json` に `saveSlotCount` / `textSpeedDefault` / `autoPlayIntervalMs` を持たせる方針

## 技術的な決定事項（実装時に判明）
- `index.html` を `file://` で直接開く運用のため、`fetch()` は使わずシナリオ/システム設定データを `scenario/sample.js`（`window.SampleScenario`）・`config/system.js`（`window.SystemConfig`）というJSファイルに格納し `<script>` タグで読み込む方式に変更（`.json` + `fetch` はChrome/EdgeでCORSエラーになるため）。データ構造自体はJSON形式のまま。
- ES Modules（`type="module"`）も `file://` でCORSエラーになるため未使用。全スクリプトはグローバル名前空間（`window.VNEngine` 等）に配置した通常スクリプトとして実装。
- 素材ファイルが無い場合のプレースホルダー表示（背景はファイル名テキスト、立ち絵は破線ボックス＋ファイル名）を実装済み。実素材を対応フォルダに配置するだけで自動的に差し替わる。
- シナリオ本文をJSON/JSオブジェクトから独自テキスト形式に変更（`js/scenario-parser.js`で解析）。同じ理由（`file://`でのCORS回避）で `.txt` 単体ファイルではなく `scenario/sample.js` 内のテンプレートリテラル文字列として保持。編集時はバッククォート内のプレーンテキスト部分のみ触ればよい。`js/engine.js`はパース後の内部データ構造のみを扱うため無改修。
- セーブ削除の確認は `window.confirm()` ではなく、削除ボタンを2回クリックする独自UI（1回目で「本当に削除？」に変化、3秒で自動キャンセル）で実装。理由: このプロジェクトのブラウザプレビュー環境で`window.confirm()`のネイティブダイアログが機能しなかったため（実ブラウザでは動く可能性はあるが、UIの一貫性のためにも自前確認方式を採用）。

## デバッグツール
- `debug.html`: シナリオの分岐をグラフィカルに表示する開発者向けビューア（ゲーム本体とは独立、`index.html`を経由しない）。詳細は[SPEC.md](SPEC.md)の該当セクション参照。
- レイアウト計算（`js/scenario-graph.js`）は開始シーンからのBFSで階層（列）を決め、未到達シーン・未定義参照シーンをそれぞれ別列に隔離して表示する。実装時、常に「未到達列」「未定義列」の幅を確保してしまいグラフが不必要に大きくなる（結果ズームアウトしすぎて見えない）バグがあったため、実際に該当ノードがある場合のみ列を確保するよう修正済み。
- 未定義シーンへの参照・孤立シーン・終端コマンド欠如の3種類の警告を自動検出し、クリックで該当ノードにフォーカスする機能を持つ。動作確認はシナリオに一時的に不正な参照を追加して実施し、正常に検出されることを確認済み（確認後は元のシナリオに戻した）。
- フラグ機能追加に伴い「フラグ」パネルを追加。シナリオ内の全フラグとその設定元/参照元シーンを一覧表示する。`@if`分岐・条件付き選択肢はオレンジ色の矢印で区別表示。

## フラグ機能（2026-09-04追加）
- シナリオ側: `@set フラグ名 値` / `@add フラグ名 数値` / `@if 条件 => シーンID`（条件付きjump、falseならフォールスルー） / 選択肢の `文言 => 次 [if 条件]`（条件付き選択肢、falseなら選択肢自体が非表示）
- 条件式は `flag` (truthy) / `!flag` (falsy) / `flag op value`（`==` `!=` `>=` `<=` `>` `<`）を解釈。値の型変換（true/false/数値/文字列）は`js/scenario-parser.js`の`normalizeValue()`にあり、`js/engine.js`の`evaluateCondition()`から`window.ScenarioParser.normalizeValue`として再利用している（ロジック重複を避けるため）
- フラグの状態(`engine.flags`)はセーブデータに含め、ロード時に復元する。新規ゲーム開始時は`engine.start()`の第4引数`flags`が未指定になり自動的に`{}`にリセットされる（`main.js`側で明示リセットする必要はない）
- サンプルシナリオに`trust`という数値フラグを追加し、機能のデモとして使用（scene2aで+1、scene3で`@if`分岐、scene3_commonの選択肢に条件付き選択肢）。ブラウザで「trust加算あり/なし」両方のルートを実際にプレイし、`@if`分岐と条件付き選択肢の表示/非表示が正しく機能することを確認済み。
