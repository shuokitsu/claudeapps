# 仕様書 - ローカルHTML SRPG（ファイアーエムブレム風）

このドキュメントはチャットでの仕様検討を反映して更新していく。「確定」「検討中」を明示し、決定した順に更新すること。

## 1. プロジェクト概要

- 種別: ローカルで動作するピュアHTML/CSS/JSのシミュレーションRPG（SRPG）
- 参考: ファイアーエムブレムのようなグリッドベース・ターン制ストラテジーRPG
- 実行環境: ブラウザで `index.html` を開くだけで動作（サーバー不要、外部ライブラリ不要）
- 画像アセット: 外部画像ファイルは持たず、SVG/CSSでキャラクターやマップを描画する（確定）

## 2. 全体構成（確定）

- マップ数: 3マップ（連続する章として順にプレイ、マップ1→2→3）
- 敵ユニット数: マップ1=6体 / マップ2=10体 / マップ3=15体
- マップサイズ: マップごとに拡大する（例: マップ1=10×8 / マップ2=12×10 / マップ3=14×11、要調整）
- マップ間の引き継ぎ: 次マップ開始時にHPは全回復、状態異常はリセットする。レベル・能力値・所持アイテム（武器・耐久度）はそのまま引き継ぐ
- 勝利条件: 各マップの敵ユニットを全滅させる（マップごと。最終マップ3をクリアしたらゲームクリア）
- 敗北条件: 主人公（王子）が戦闘不能になる

## 2-1. 地形（確定方針）

数種類の地形を用意し、移動コスト・回避補正に影響させる。

| 地形 | 移動コスト（初期案） | 回避補正（初期案） | 備考 |
|---|---|---|---|
| 平地 | 1 | +0% | 基本地形 |
| 森 | 2 | +20% | 移動は遅くなるが隠れやすい |
| 山 | 3 | +30% | さらに移動コストが高い |
| 壁・建物 | 進入不可 | - | ユニット・射線を通さない障害物 |

- 具体的な数値・地形種類の追加（城・川など）は実装時に調整
- マップごとに地形の配置パターンを変える（マップが進むほど複雑にする想定）

## 3. プレイヤーユニット（確定）

4体固定編成。

| ユニット | 役割 | 特徴 | 使用武器 |
|---|---|---|---|
| 王子 | 主人公・全体の要 | バランス型。戦闘不能=ゲームオーバー | 剣（射程1） |
| 重兵 | 前衛タンク | HP・防御が高い、移動力は低め | 槍または斧（射程1） |
| 魔導士 | 遠隔攻撃 | 攻撃力高いが防御低い、射程を活かして後方から攻撃 | 魔道書（射程1〜2） |
| 僧侶 | 支援・回復 | 攻撃力は低い（または無し）、味方回復役 | 杖（射程1〜3、回復専用） |

各ユニットの初期ステータス・成長率は実装時にバランス調整しながら決める（デフォルト値は要調整）。

## 4. 武器・射程（確定方針）

武器種によって射程・威力・耐久度が異なる。

| 武器種 | 射程 | 用途 | 耐久度（初期案・要調整） |
|---|---|---|---|
| 剣 | 1 | 近接攻撃 | 30〜40 |
| 槍・斧 | 1 | 近接攻撃（重兵用） | 30〜40 |
| 魔道書 | 1〜2 | 近接〜中距離の魔法攻撃 | 20〜30 |
| 杖 | 1〜3 | 味方の回復（攻撃不可） | 15〜20 |

- 耐久度が0になった武器は使用不可（破損）になる（確定：武器管理あり）
- ユニットは複数の武器を所持でき、戦闘前に使用武器を選択・持ち替えできる（インベントリ機能）
- 各ユニットの所持数上限は要検討（デフォルト案: 4〜5個）

## 5. 戦闘計算（提案・要確認）

- 命中率 = 攻撃側の命中 - 防御側の回避（0〜100%でクランプ）
- ダメージ = 攻撃側の攻撃力（武器補正込み） - 防御側の防御力（最低1ダメージ保証、要確認）
- クリティカル・武器三属性（剣・槍・斧の三角関係）は今回は対象外とする（要確認：入れる場合はSPECに追記）
- 杖（回復）は対象の武器射程内にいる味方1体のHPを回復する

## 6. 成長・レベルアップ（確定方針）

- 戦闘（攻撃・被弾・回復・撃破）でEXPを獲得する
- EXPが一定値に達するとレベルアップし、成長率（%）に応じて能力値（HP/攻撃/防御/命中/回避/移動 等）がランダムに上昇する、classic FE方式
- 具体的なEXP計算式・成長率・最大レベルは実装時に決定（デフォルト値は要調整、バランスはマップ2・3の敵増加に合わせて調整する）
- クラスチェンジ・武器熟練度は今回は対象外

## 7. セーブ・ロード（確定）

- localStorageを使用したセーブ・ロード機能あり
- 保存内容: 現在のマップ進行状況、各ユニットのレベル・能力値・所持武器（耐久度含む）・EXP
- セーブ/ロードのUI: メニューから手動セーブ、タイトル画面またはメニューからロード（詳細は実装時に決定）
- セーブスロット数（1つ or 複数）は要検討（デフォルト案: 1スロット）

## 8. ビジュアル表現方針（確定）

- 画像ファイルを使わず、SVGまたはCSS図形でユニット・マップタイルを表現する
- ユニットは色分け＋簡易アイコン（職業や陣営を区別するための図形）で表現
- 将来的にドット絵などの画像アセットに差し替え可能な構造にする（表示コンポーネントを分離しておく）

## 9. 技術構成（提案）

- `index.html`: エントリーポイント
- `style.css`: 見た目・レイアウト（CSS Gridでマス目を表現）
- `js/` 以下にロジックを分割
  - `main.js`: 初期化・ゲームループ・画面遷移（タイトル/マップ選択/戦闘/メニュー）
  - `map.js`: マップ・グリッド管理（3マップ分のデータ）
  - `unit.js`: ユニットのデータ・行動・成長処理
  - `battle.js`: 戦闘計算
  - `ai.js`: 敵AIロジック
  - `inventory.js`: 武器・所持品・耐久度管理
  - `save.js`: localStorageへの保存・読み込み
  - `render.js`: 描画（DOM/SVG操作）
- フレームワーク不使用（ピュアHTML/CSS/JavaScript、確定）

## 10. データ構造（ドラフト）

```js
// ユニット
{
  id: string,
  name: string,
  class: "prince" | "heavy" | "mage" | "priest" | ...(敵クラス),
  team: "player" | "enemy",
  level: number,
  exp: number,
  hp: number, maxHp: number,
  atk: number, def: number, mag: number,
  move: number,
  hit: number, avoid: number,
  growth: { hp: number, atk: number, def: number, ... }, // 成長率(%)
  inventory: Weapon[],
  equippedWeaponId: string,
  x: number, y: number, // グリッド座標
}

// 武器
{
  id: string,
  name: string,
  type: "sword" | "lance" | "axe" | "tome" | "staff",
  range: [min, max],
  might: number, // 威力
  durability: number,
  maxDurability: number,
}

// マップタイル
{
  x: number, y: number,
  terrain: "plain" | "forest" | "wall" | ...,
  moveCost: number,
}

// セーブデータ
{
  currentMapIndex: number,
  units: Unit[], // 味方ユニットの現在状態
  savedAt: string,
}
```

## 12-1. 会話パート（確定・実装済み）

- 各マップ開始前（intro）・クリア後（outro）に、会話専用画面を挿入する
- キャラクターは画面左右に表示（左＝レオン王子で固定、右＝会話中の相手が入れ替わる）。見た目はCSSの円形＋漢字グリフ（既存のユニット表現と統一）＋名前表示
- 各マップintroの最後に選択肢があり、選ばれた選択で敵ステータス（攻撃・防御）に補正が入り、難易度が変化する
- ストーリー・キャラクター設定:
  - レオン（王子・主人公）／ガレス（重兵・忠実な老練の騎士）／ミレイ（魔導士・皮肉屋だが実力者）／セリア（僧侶・心優しい回復役）
  - 敵将グロムの侵略軍に王都を落とされたところから始まり、王都陥落→谷間の攻防→決戦、で王都奪還を目指す3章構成
- データ・再生エンジンは [js/dialogue.js](js/dialogue.js) にまとめている（会話内容の追加・修正はこのファイルを編集する）
